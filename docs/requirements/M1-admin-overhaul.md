# M1 요구사항 — 관리자 화면 개편

대상 파일: `admin.html`, `js/admin.js` (필요 시 `js/store.js`에 함수 추가)
배경: [개발계획서 §2](../development-plan.md) · 구조 규칙: [architecture.md](../architecture.md) · 공통 규칙: [AGENTS.md](../../AGENTS.md)

공통 원칙
- 기존 디자인 언어(색·radius·Pretendard·인라인 스타일, admin.js의 `S` 스타일 조각)를 그대로 사용한다.
- 저장은 기존처럼 즉시 저장 + "✓ 저장됨" 플래시 유지.
- 모바일 폭(<900px)에서도 목록·폼이 깨지지 않아야 한다.

## R1. 공지사항 관리 게시판형 전환

현재: 모든 공지가 인라인 수정 카드로 전부 나열됨 (admin.js `renderNoticeTab`).

### 요구사항

1. **목록 화면** (공지 탭 기본 화면)
   - 행 구성: [고정 아이콘] [태그 칩] 제목 · 날짜 · [수정] [삭제] 버튼
   - 정렬: 고정 글 먼저, 그다음 최신순
   - 페이지네이션: 10건 단위, 하단에 `◀ 1 2 3 ▶` 형태 (현재 페이지 강조)
   - 검색: 상단 검색창, 제목+본문 부분일치, 입력 시 즉시 필터(디바운스 불필요)
   - 상단 우측 [+ 새 공지] 버튼
2. **작성/수정 화면** (목록과 화면 전환, 모달 아님)
   - 필드: 태그(선택) · 제목(필수) · 내용(필수) · 상단 고정 체크박스
   - 첨부파일 영역: 파일 선택 UI만 배치하고 비활성 + "서버 연동 후 활성화" 안내 라벨
     (실제 업로드는 M3 — 지금 동작하게 만들지 말 것)
   - [등록/수정 저장] [취소] 버튼. 유효성 실패 시 기존 방식대로 인라인 에러 문구
3. **삭제**: confirm 모달(기존 "기본값 되돌리기" 모달 스타일 재사용)
4. **데이터**: notice 객체에 `pinned: boolean` 필드 추가 (기존 데이터에 없으면 false 취급).
   store.js의 기본 데이터는 수정하지 않는다.
5. **사용자 화면 연동**: notice.html 목록에서 pinned 글을 최상단에 📌 표시로 노출
   (이 항목만 `js/notice.js` 수정 포함)

### 완료 기준
- 공지 30건 입력 상태에서 검색어로 3초 내 특정 글 도달, 페이지 이동 정상
- 고정 글이 관리자·사용자 양쪽 목록 최상단에 표시
- 새 공지 등록/수정/삭제 후 목록·사용자 화면·localStorage 모두 일관

## R2. 문의 답변 관리 개선

현재: 아코디언 전체 나열 (admin.js `renderInquiryTab`).

### 요구사항

1. **필터 탭**: [전체] [답변대기 (N)] [답변완료] — 답변대기 탭 라벨에 건수 뱃지
2. **검색**: 제목·이름·연락처 부분일치
3. **페이지네이션**: 10건 단위 (R1과 동일한 컴포넌트 스타일)
4. **상세 화면**: 행 클릭 시 아코디언 대신 화면 전환
   - 표시: 상태 칩, 제목, 날짜, 이름/연락처/이메일, 문의 내용(견적 첨부 포함 원문),
     답변 텍스트영역, [답변 등록/수정] [삭제] [목록으로]
   - 답변 저장 시 상태 자동 변경(기존 로직 유지)
5. **요약 카드**: 관리자 페이지 진입 시 탭 바 위에 한 줄 요약
   - "답변대기 문의 N건 · 공지 N건 · 품목 N개" — 답변대기 부분 클릭 시 문의 탭+대기 필터로 이동

### 완료 기준
- 문의 30건에서 "답변대기" 필터 + 검색 조합 정상
- 목록 → 상세 → 답변 저장 → 목록 복귀 시 필터·페이지 상태 유지

## R3. 할인 설정 UI 개편

현재: 사용/방식/값 버튼 분산, 정액 선택 시 품목별 입력이 카탈로그 탭 4곳에 흩어짐.

### 요구사항

1. **요약 카드** (할인 탭 최상단): 현재 설정을 한 문장으로
   - 예: "현재 적용 — 기본 5% 할인 · 제휴 12% 할인" / 꺼져 있으면 "기본 할인 사용 안 함"
2. **섹션 한 줄 구성**: 기본/제휴 각각
   - `[ON/OFF 토글] (● 퍼센트 ○ 정액) [값 입력] 단위`를 한 행에 배치
   - OFF면 방식·값 영역을 흐리게(disabled), 펼침 상태는 유지
3. **적용 예시 미리보기**: 값 변경 즉시 갱신
   - 퍼센트: "종일권 55,000원 → 52,250원" (카탈로그 첫 품목 기준)
   - 정액: "1개당 3,000원씩 할인"
4. **품목별 정액할인 테이블**: 할인 탭 안에 통합 (정액 선택된 할인이 하나라도 있을 때만 표시)
   - 컬럼: 품목(카테고리 그룹핑) · 가격 · 기본할인(원) · 제휴할인(원)
   - 값 0 또는 빈칸이면 "기본값 사용" 처리 (기존 로직과 동일)
   - **카탈로그 탭(리프트권 등)에 있던 품목별 할인 입력칸은 제거**
5. 제휴 키워드 관리는 기존 UI 유지

### 완료 기준
- 할인 상태가 요약 카드 한 줄로 파악 가능
- 정액 전환 시 품목별 설정을 테이블 한 곳에서 완결
- 셀프견적 → 문의 첨부의 할인 계산 결과가 개편 전과 동일 (회귀 없음)

## R4. 품목 관리 보완

1. **순서 변경**: 각 품목 행에 ↑/↓ 버튼 — 셀프견적 노출 순서에 반영 (배열 순서 = 노출 순서)
2. **품절/숨김 토글**: Item에 `hidden: boolean` 추가. 숨긴 품목은 셀프견적(estimate.js)
   목록에서 제외, 관리자에서는 흐리게 표시 (estimate.js 수정 포함)
3. **가격 표시**: 목록의 가격 입력에 천단위 콤마 표시 (저장값은 숫자 유지)

### 완료 기준
- 순서 변경·숨김이 셀프견적 화면에 즉시 반영 (같은 탭 새로고침 기준)
